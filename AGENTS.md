# Aeris — обязательные инструкции разработчикам и ИИ-агентам

## 1. Источник требований

Перед началом задачи читать SPECIFICATION, ARCHITECTURE, ROADMAP, CONFIGURATION, PROVIDER-HEADERS, UI-SPECIFICATION, TESTING, COMPATIBILITY. Позднее явно утверждённое решение пользователя отменяет противоречащее раннее. Не расширять scope ради количества функций. Если контракт не утверждён, помечать TBD, не выдавать предположение за решение. Согласовывать существенные изменения. Не считать этот комплект существующим кодом или проверенными результатами.

## 2. Не нарушать

- Aeris — отдельный проект; не менять FlClashZ, его службы, файлы, ветки или automations.
- Windows 11 x64 / Windows 10 22H2 x64. Core Rust, GUI C#/WinUI3. Не подменять ядро внешним Mihomo/Xray/winws. Не добавлять Zapret1, самописную криптографию или C DPI FFI.
- Эталон Mihomo — сборка FlClashX. XHTTP/XUDP/REALITY/Vision — оригинальный Xray, DPI/Lua — Zapret2. Соблюдать лицензии, фиксировать ссылки и commits. Не копировать чужой код без проверки права использования.
- VPN/DPI независимы, DNS имеет собственный lifecycle. Не модифицировать прокси-транспорт DPI по умолчанию. Не допускать скрытых утечек или обхода Kill Switch. Не выполнять произвольные BAT/CMD/Lua OS commands от SYSTEM.
- CLI `aeris` из любой директории pwsh, GUI `Aeris.exe`, ядро `aeris-core.exe`, сервис `AerisCore`. Не полагаться на регистр файлов Windows. Не создавать alias clash.
- YAML подписки неизменяем, пользовательские правила отдельно и приоритетнее. Не вводить общий override, `nooverride`, Lua config overrides. Отдельный адаптированный Mihomo template Remnawave.
- Только два режима UI: без providermode простой, с providermode полный. Нет ручного переключателя, редактирования виджетов, IP в простом; полный IP всегда при наличии, без анонса. Соблюдать согласованное размещение UI и общий hover glow. Не возвращать старые макеты, popup выбора или ранее отвергнутые функции.
- Release/Nightly, без Preview. Нет отдельного полного backup/export настроек. Внутренний rollback остаётся. Не публиковать стабильный Release до gate 1.0.0.
- Не вводить телеметрию, аккаунты, лишние зависимости, неподтверждённые параметры и скрытые fallback. Не логировать токены/приватные ключи/полные URL подписок без защиты.

## 3. Рабочий процесс

1. Проверить актуальную ветку, файлы, требования и upstream refs. Не путать эталон с целевым репозиторием.
2. Сделать минимальный согласованный план, определить затронутые модули и тесты.
3. Изменить код, тесты, схемы/контракты и документацию совместно. Не оставлять дублирующий код и необъяснённый unsafe.
4. Запустить доступные проверки, сообщить команды, результаты, ошибки и недоступные среды. Не выдавать сборку за тестирование. Не отмечать непроведённый тест как PASS.
5. Проверить security, regressions, error paths, IPC compatibility, rollback и производительность по необходимости.
6. Подготовить проверяемый diff/PR, provenance, ограничения. Не сливать при fail обязательных тестах.
7. Создавать/изменять репозитории, запускать сборку, публиковать Release и менять инфраструктуру только в рамках полученного разрешения. Не запускать сборки в ответ на обсуждение дизайна или подтверждение пункта ТЗ.

## 4. Качество и безопасность

Rustfmt/Clippy/Cargo Test/Audit/Deny, Roslyn/dotnet format, unit/integration/fuzz. Асинхронность, bounded queues, cancellation, typed errors. Минимальные права, IPC ACL, явные capabilities, подписанные манифесты с доверенными ключами, хэши, atomic replace, path validation, архивы без traversal. Никаких случайных privileged shell scripts. Lua sandbox/изоляция по threat model, проверка лицензий/подписей ресурсов. Секреты DPAPI/redaction; нет автоматической отправки логов.

## 5. Отчётность

Отдельно указывать: что реализовано, что проверено, что не проверено и почему, что осталось, какие предположения сделаны. Утверждения о производительности и совместимости — только на основе реальных измерений/версий. Никаких обещаний фоновой работы без созданного механизма автоматизации. В каждом релизе обновлять документацию RU/EN, changelog, матрицу совместимости и manifest.
