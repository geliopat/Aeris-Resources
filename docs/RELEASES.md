# Release and Nightly — gates

Independent versions start at 0.1.0. Release requires manual approval and all requirements in the canonical Aeris-Core TESTING.md. Nightly requires actual implemented functionality, passing mandatory CI, and a change since its previous build; use a unique UTC date/run identifier. Never publish unsigned manifests or unsupported driver packages. Initial CI only builds/tests the scaffold; no publication, signing, or automatic release workflow is enabled. Add release automation only after signing trust roots, artifact layout, rollback and real Windows validation are established. Preview channel is excluded.
